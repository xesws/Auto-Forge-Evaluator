## 1. An undeclared feature-definition change

Location: `analysis_v2.py::format_compliance_base`, branch
`task_id == 'math' -> base['boxed'] / n`. It is **not** among the eight
declared items of `ANALYSIS_PREREG_V2` (see that file's late declaration R1-9).

The v1 formula `1 - unparseable/n` returns 1.0 for any task whose
format-compliance block has no `unparseable` key. Exactly two of the 61 tasks
are shaped that way:

| task | scalar keys in the base block | v1 value | v2 value |
|---|---|---:|---:|
| `gsm8k` | `diverge`, `hash`, `last_only`, `n`, `none` | 0.290 | 0.290 |
| `math` | `boxed`, `diverge`, `last_only`, `n`, `none` | 1.000 | 0.550 |

v1 special-cased `gsm8k` and missed `math`. **The branch is a genuine bug fix,
not a per-task choice** — but the only task it changes, `math`, is one of only
two substantive negatives in the whole sample.

## 5. The reading the paper adopts

1. The registered row (12 features, including the post-decision
   `gen_len.full.median`) is AUC 0.755, CI covers 0.5: **published as a
   negative**.
2. Removing that post-decision feature does **not** rescue it.
3. Only a parsimonious three-feature pre-decision model is significant. The
   registered negative is best read as **over-parameterisation** (12 features
   against 8 negatives), not as an absence of signal.
4. The MATH format-compliance bug fix is declared separately with its own
   effect size and is **not** folded into "removing leakage".
5. The gate was low-value regardless: a perfect gate is worth 0.024 of
   positive-gain mass over always forging.
